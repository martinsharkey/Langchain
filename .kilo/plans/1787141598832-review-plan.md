## Phase 1 — mt5_lock coverage (finding #87)

**Goal:** every `mt5.order_send`, `mt5.positions_get`, `mt5.history_deals_get`, and `mt5.copy_ticks_range` call is serialized behind `mt5_lock()`.

### 1.1 Wrap `src/mt5/orders.py`
- Import `mt5_lock` from `src.mt5.connector`.
- Wrap these calls with `with mt5_lock():`:
  - `_place_order_via_silicon`: `silicon_mt5.order_send(request)` (line 158), plus the preceding `positions_get`/`symbol_info_tick` reads that feed it.
  - `_place_order_native`: `mt5.order_send(request)` (line 230), plus `mt5.symbol_info_tick` (line 208).
  - `_close_order_via_silicon`: `silicon_mt5.positions_get` (line 321), `silicon_mt5.symbol_info_tick` (line 331), `silicon_mt5.order_send` (line 352).
  - `_close_order_native`: `mt5.positions_get` (line 380), `mt5.symbol_info_tick` (line 390), `mt5.order_send` (line 411).

### 1.2 Wrap direct `mt5.*` reads in `src/trading/scalp_engine.py`
| Line | Call | Context |
|---|---|---|
| 754 | `mt5.positions_get()` | `_adopt_existing_positions` |
| 834 | `mt5.positions_get()` | `_reconcile_pending_from_db` |
| 894 | `mt5.history_deals_get()` | `_deal_result_by_ticket` |

Wrap each with `with mt5_lock():`. Keep lock scope tight.

**Acceptance criteria:**

## Phase 2 — EA generator tests and hardening (findings #89, #91, #92)

**Dependencies:** Phase 1 complete and merged.

### 2.1 Add `tests/test_ea_generator.py`
Create tests for `scripts/qmmp/ea_generator.py`:

| Test | Assertion |
|---|---|
| `test_build_ea_groups` | Input block has exactly 7 groups with counts: core=5, session=11, entry=3, floors=21, exit=7, mm=2, logging=1 |
| `test_deterministic_magic` | `Magic` input equals `config.magic_for_symbol(sym)` |

| `test_params_json_matches_manifest` | `.params.json` equals the `manifest` dict from `build_ea` |

### 2.2 Harden EA `MaybeReloadModel()` in generated MQ5
Update the template string in `scripts/qmmp/ea_generator.py`:

- Wrap `ReadFileText(path)` and JSON extraction in try/except.
- If file missing or parse fails: log `[QMMP] Reload failed`, leave all `g_ov_*` globals at 0 (use input defaults).
- Add range checks: if reloaded value is outside the corresponding input's declared `[lo, hi]` range, log `[QMMP] Reload value X out of range for Y` and ignore it.
- If a field is absent from `model.json`, leave its override at 0.

### 2.3 Extend EA lifecycle log
In the EA template in `scripts/qmmp/ea_generator.py`:

- Add `LogVersion` input (default 2). Version 1 = current entry-only schema. Version 2 = extended schema below.
- Add columns: `ExitPrice`, `ExitSL`, `ExitReason`, `MFE`, `MAE`.
- Add `LogModify(ticket, old_sl, new_sl)` and `LogBE(ticket, new_sl)` helper functions.
- Call `LogModify` from `ModifyAllSL`; call `LogBE` when BE lock first arms (inside `ManageBasket`).
- When `LogVersion >= 2`, `EnsureLog()` writes the extended header and all events populate the new columns.

**Acceptance criteria:**
- `pytest tests/test_ea_generator.py -v` passes.
- `python -m scripts.qmmp.ea_generator BTCUSD --verify` passes against current `data/qmmp/BTCUSD/model.json`.
- Generated EA compiles in MT5 Strategy Tester (manual check by developer).
- Corrupt `model.json` → EA logs reload failure and trades with input defaults (manual test).
- New lifecycle CSV contains entry + modify + BE + close rows with all columns populated.

## Phase 3 — Dukascopy fidelity validation (finding #88)

**Dependencies:** Phase 1 and 2 complete and merged.

### 3.1 Overlap window comparison
- Pick 1 recent week of XAUUSD M1 data (e.g., 2026-08-10 to 2026-08-17).
- Fetch via both `src.data_sources.dukascopy.DukascopySource.get_rates` and `src.mt5.data.get_rates` (MT5).

**Acceptance criteria:**
- `docs/dukascopy_fidelity.md` exists with concrete numbers and a pass/fail verdict.
- `src/learning/adaptive_loop.py` and `src/trading/scalp_engine.py` respect the fidelity finding (either no change if validated, or dual-source gate if diverged).
